- Cloud workerd suite: **139 tests passed** across 19 files. Combined TypeScript/cloud total: **1,686**.
- `bun run swift:test`: all ordinary suites, registered main-serial-executor suites, and screen-sharing rig tests passed on the final Swift source state.
- Focused TypeScript regressions passed again with shuffled order (seed 851), ordinary parallel execution, and no retries.
- Touched-package typechecks (27 dependency tasks), JS/Swift formatting and lint, line-count ratchet, module boundaries, and whitespace checks passed.
- `bun run dev:scripts:test`: 78 Node tests and four Bun tests passed. `bun run release:scripts:test`: 91 tests passed.
- `bun run dev:macos --no-containers`: successful build and launch. `bun run build:ios`: successful simulator app build.

Baseline experiments used an isolated archive of the audited revision, plus controlled temporary restoration of native owners. Fixed files were restored before final verification. No source was edited while tests were running. Detailed local logs are under ignored `tmp/race-audit/`.

## Workflow observations

The macOS development app used the hazelnut checkout, local server on port 55054, and isolated local development cloud. Development-account sign-in, project registration, and ordinary prompt/follow-up responses passed. A split workspace opened alongside the transcript and retained both panes when navigating away and returning. On Dev Cloud, Go to Folder loaded the temporary project directory; creating a subfolder refreshed the parent listing immediately and selected the new folder.

A separate actual-runtime workflow used production MCP scanning/editing, temporary JSONC configuration files, and SQLite. Two concurrent removals preserved unrelated settings and the original backup; two concurrent restores recovered both entries; a stale conditional write was refused without losing an external edit. Temporary harness configuration data was removed afterward. The owned macOS development runner and app were stopped after verification; the reproducible temporary project remains under ignored `tmp/race-audit/`.

## Limits

- iOS interaction was blocked by the simulator launcher's Xcode Accessibility error: `Cannot read AXWindows from Xcode (AX error -25204)`. The iOS build passed; no iOS UI workflow is claimed.
- Screenshot timeout ownership was repaired and compiled, but was not exercised with live timeout injection or Thread Sanitizer. The development app's own capture permissions were not granted during this check.
- Native configuration locking coordinates Codevisor editor instances in one process. External harness writers do not participate. Revalidation detects intervening writes, but the filesystem does not offer an atomic content compare-and-swap across validation and rename.
- Artifact lock safety applies to the new directory protocol. Older processes using the legacy PID-file writer do not participate in that protocol.
