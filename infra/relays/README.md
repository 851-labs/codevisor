# Tunnel relays

The Codevisor tunnel's relays (see [the plan](../../docs/plans/codevisor-tunnel.md)).
Devices connect to each other directly whenever they can. The relays do two
things:

- they tell each device its public address (QUIC address discovery, UDP 7842);
- they carry traffic for connections that can't go direct, over HTTPS/WebSocket
  on 443, encrypted end to end so the relay can't read it.

Each relay is its own Fly.io app with one Machine, a dedicated IPv4 and IPv6,
and a 1 GB volume for its certificate. `relays.json` is the source of truth.

## Files

| File                  | What it is                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `relays.json`         | Every relay instance. `advertise` controls whether the cloud hands it to devices.                    |
| `fly/*.toml`          | Fly config per relay, generated by `node gen-fly.mjs` (CI fails on drift).                           |
| `Dockerfile`          | Pinned iroh-relay binary (URL + sha256 from `scripts/net-build.lock.json`), certbot, and the router. |
| `entrypoint.sh`       | Fly bind resolution, the port-80 router, certbot, then the relay.                                    |
| `render-config.sh`    | The one place the relay config is written. `bun run dev` uses it too.                                |
| `port80-router.py`    | Port 80: Let's Encrypt HTTP-01 challenges, and everything else forwarded to the relay.               |
| `provision.mjs`       | Idempotent Fly app, IPs, volume, secret, and Cloudflare DNS for one relay.                           |
| `smoke.mjs`           | Image smoke test (throwaway CA) and live-relay checks.                                               |
| `check-relay-map.mjs` | Checks `apps/cloud/wrangler.jsonc` `RELAY_MAP` matches the advertised relays.                        |

## Certificates

Each relay gets its own Let's Encrypt certificate with the HTTP-01 check on
port 80, through `port80-router.py`, and certbot renews it inside the Machine.
The relay loads it in `Reloading` mode, so renewals apply within a day with no
restart. No DNS or ACME credentials live on the relays.

The relay's built-in ACME can't be used on Fly: Fly's proxy answers the
TLS-ALPN-01 check (`acme-tls/1`) itself. Fly-managed certificates can't be used
either: Fly never exposes their private keys, and QUIC address discovery needs
the certificate on the relay.

## Deploying

Everything deploys from `main` through `.github/workflows/deploy-relays.yml`.
The workflow builds the image once, smoke-tests it, pushes it to
`registry.fly.io/codevisor-relay`, then provisions and deploys one relay at a
time, running the live smoke test after each one.

Each relay has a single Machine, so a deploy restarts that relay. Direct
connections don't notice. Connections going through it pause for a few seconds
and continue on the same connection: in the spike, a restart caused one 3.9 s
stall and no reconnect, and `scripts/net-e2e.mjs` checks this on every CI run.

### Secrets

- `FLY_API_TOKEN` (GitHub environment `relays-production`): org deploy token (`fly tokens create org --expiry 8760h`).
- `CLOUDFLARE_API_TOKEN` (repository secret): the same token `deploy-cloud.yml` deploys the Worker with. `provision.mjs` also needs it to have Zone → DNS → Edit and Zone → Zone → Read on `codevisor.dev`; it finds the zone by name.
- `RELAY_AUTHORIZE_TOKEN` (repository secret, read by both deploy workflows): relays present it to `POST /api/relay/authorize`. The Worker has the same secret (`deploy-cloud.yml` syncs it), and accepts a comma-separated list, so it can be rotated with no downtime.

## Adding a relay (two PRs)

1. Add the relay to `relays.json` with `"advertise": false`, then run `node infra/relays/gen-fly.mjs`. Merging deploys it and smoke-tests it.
2. Set `"advertise": true` and add its URL to `RELAY_MAP` in `apps/cloud/wrangler.jsonc` (`check-relay-map.mjs` enforces the match). Merging starts handing it to devices.

## Removing a relay

1. Set `"advertise": false` and remove it from `RELAY_MAP`. Devices move off it the next time they connect.
2. A day later, delete the entry and its `fly/*.toml`, then run `flyctl apps destroy codevisor-<id>` and delete its DNS records. This is the only manual step.

## Local development

`bun run dev` runs two relays from the same pinned binary, configured by the
same `render-config.sh` and fronted by the same router, with a per-worktree dev
CA instead of Let's Encrypt (`scripts/dev-net.mjs`). `scripts/net-e2e.mjs` runs
the whole stack (wrangler, relays, servers, a headless app) the same way.
