A Codevisor plugin is an MCP server. Codevisor connects to it over stdio or Streamable HTTP, exposes
its tools to agent sessions through the Codevisor gateway, and reads the extensions the server
declares in `capabilities.extensions`:

| Feature                 | Mechanism                                                                    |
| ----------------------- | ---------------------------------------------------------------------------- |
| Tools                   | Standard MCP `tools/list` and `tools/call`                                   |
| Skills                  | MCP Skills, `io.modelcontextprotocol/skills`                                 |
| Inline UI in chat       | MCP Apps, `io.modelcontextprotocol/ui`, on tools with `_meta.ui.resourceUri` |
| Events that wake agents | `io.modelcontextprotocol/events`, shaped like MCP Events (SEP-3415)          |
| Workspace panes         | `dev.codevisor/panes`                                                        |
| Inbound webhooks        | `dev.codevisor/webhooks`                                                     |

Any MCP server works as a plugin; the extensions are optional. Each Mac connects to its plugins
itself, and a local plugin runs on that Mac, so its tools act on that machine.

## Install and manage

Plugins live on one **Plugins** page in Settings, on macOS and iOS.

- **Browse Plugins…** installs from the Codevisor catalog: plugins by Codevisor and a curated list
  of popular MCP servers. Plugins that run locally ship with Codevisor itself; hosted ones connect to
  the publisher's MCP URL.
- **Add MCP…** takes a Streamable HTTP URL such as `https://mcp.example.com/mcp`, or a command
  such as `node /absolute/path/server.js` that Codevisor starts on the machine.

Installed plugins sync to every Mac signed in to your Codevisor account. Turn a plugin off and on to
restart a local server; Codevisor rereads its tools, skills, and events when it reconnects.

## Accounts

A plugin that talks to another service signs in once, and the account works on every Mac:

- **OAuth.** Hosted MCP servers use standard MCP OAuth. Plugins that wrap a service declare a
  provider and scopes, and Codevisor runs the sign-in. Google requires your own OAuth client: create
  one in the Google Cloud console and enter its client ID and secret when you add the account.
- **Fields.** Plugins can ask for values such as a URL or an API key.

Tokens and secret fields are stored in the shared credential vault and synced to every Mac. Codevisor
refreshes OAuth tokens itself; a plugin receives only the current access token and field values, on
each request it handles. A plugin can have several accounts, and agents choose one per tool call.

## Events

Plugins that declare events let agents wait for something to happen instead of polling. An agent
lists the available events with `events.topics` and subscribes with `events.subscribe`, optionally
with a [CEL](https://cel.dev) filter over the event payload:

```text
labels.severity == "critical" && labels.env in ["prod", "staging"]
```

Codevisor type-checks the filter against the event's payload schema and reads it back in plain
English. Each match wakes an idle agent, or waits for the end of its current turn. Subscriptions
survive restarts, and each Mac runs an event source only while one of its agents is subscribed.

Webhook events reach a Mac through a cloud inbox. Codevisor gives each plugin account a webhook URL
to enter in the provider. The inbox seals every request separately for each device with a subscriber
and holds it until that device takes it, so a sleeping Mac catches up when it wakes. The plugin
verifies and normalizes the request on the Mac; nothing runs in the cloud.

## Inline UI and panes

A tool that declares an MCP Apps `ui://` resource renders that UI inline in the chat transcript with
its result. A plugin can also declare panes in `dev.codevisor/panes`; each opens as a workspace tab
that renders the plugin's `ui://` page through the same Apps bridge.

## Build a plugin

Ask an agent in Codevisor to build one. The built-in `create-codevisor-plugin` skill covers the
server template, every extension, accounts, and testing with the MCP Inspector, and ends by adding
the server through **Add MCP…**.

Plugins are stored as MCP servers, so the [MCP server routes](/docs/mcp) manage installed plugins.
The [Plugins API](/docs/api-reference/plugins/get-plugins-catalog) covers the catalog, accounts, and
event subscriptions.

<Callout type="warning" title="Experimental extensions">
  The Codevisor extensions and the MCP Events draft can change between Codevisor releases. Pin the
  release you build and test against.
</Callout>
